### What the script does

#### Step 1 — SDK initialisation
```python
composio = Composio()
```
The SDK picks up the API key from the environment automatically.

#### Step 2 — Create / upsert the trigger
```python
composio.triggers.create(
    slug="GITHUB_ISSUE_ADDED_EVENT",   # confirmed slug via list_enum()
    user_id="zealt-user01",
    trigger_config={"owner": "composiohq", "repo": "composio"},
)
```
`GITHUB_ISSUE_ADDED_EVENT` fires a webhook payload containing `number`, `title`, `description`, `createdBy`, and `url` every time a new issue is opened on the target repo.

#### Step 3 — Subscribe and handle events
```python
subscription = composio.triggers.subscribe()

@subscription.handle(trigger_slug="GITHUB_ISSUE_ADDED_EVENT", user_id="zealt-user01")
def on_issue_opened(event: TriggerEvent) -> None: ...
```
The handler extracts `issue_number`, `issue_title`, and `issue_body` from the webhook payload.

#### Step 4 — Sentiment analysis inside the Workbench
The handler calls `composio.tools.execute("COMPOSIO_REMOTE_WORKBENCH", ...)` with a Python script that:

1. **Heuristic analysis** — searches the combined title + body for ~30 negative keywords (`bug`, `crash`, `error`, `critical`, `regression`, `vulnerability`, etc.).
2. **If negative** → calls `run_composio_tool("GITHUB_ADD_LABELS_TO_AN_ISSUE", {..., "labels": ["urgent"]})` inside the sandbox, which already has the user's GitHub connection in scope.
3. Prints a full diagnostic (matched keywords, sentiment verdict, label response).

Runtime values (title, body, issue number, repo coordinates) are injected as variable assignments prepended to the sandbox code, with backslash/quote escaping to prevent injection from issue content.

#### Step 5 — Wait forever
```python
subscription.wait_forever()
```
Keeps the process alive and prints `"Pipeline active"` before blocking.
